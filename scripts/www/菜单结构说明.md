# 设置面板 · 菜单数据结构与渲染逻辑（v43）

> **v43 变更（八条整改需求；本节只记**数据结构 / 渲染口径**的变化，界面文案见 `使用说明.txt`，
> 物理位置与窗口布局见 `菜单与窗口布局结构.md`）**：
> ① **线宽全部改为「相对倍率」口径（需求一·3 / 三·1）** —— 全站线宽控件原有五套互不相容的单位与量程。
>   方案是**不改渲染代码、不改状态物理单位**（度 / 世界单位），只给每条路径登记一个基准值
>   （= 旧默认值 = 视觉 1.00×），滑块一律 **10–300 / step 1 = 0.10×–3.00×**，读数一律「1.00×」。
>   新增两个 DSL 记录器包装（等价于 `rg`，只是把量程与 map/fmt 固定住）：
>   `menu.js` 的 `lwCtl(id, name, path, out)` 与 `sunview.js` 的 `svLwCtl(...)`，
>   分别替换 18 个与 13 个 `rg()` / `use()` 字符串 id；配套 `app.js` 的 `MAPS.lwRel` + `FMTS.lwX`、
>   `bindRange` 的 `__lwRel` 分支，以及 `sunview.js` 的 `SV_LW_BASE` / `svLwMult` / `svLwFromSlider`。
>   ⚠️ **写工具脚本时注意**：`tools/_dump_menus.js` 在 Node 里 eval 菜单数据、不引产品代码，
>   必须自行复刻 `lwCtl` / `svLwCtl` 两个包装，否则 `ReferenceError` 直接导出失败。
> ② **天球当日轨道改为 `TubeGeometry` 细管** —— 此前是 1px WebGL 线，`线粗细` 调了没有任何效果；
>   半径取 `max(0.003, SV_CEL_TRAJ_R × 倍率)`，地平线下按 `um2 < 0.45` 分虚线 / 细管。
>   因为几何变了，`S.traj.w` **必须纳入 `trailSig` 签名**才会触发重建。
> ③ **全站字号口径统一（需求三·2）** ——
>   (a) `textSprite` 的 `baseSize` 缺省值由魔数 `0.6` 改为**分类固有值** `svNoteStyle(cat).size`
>       （即 `NOTE_CAT_DEF` 里的默认值）。旧写法的问题是各调用点自己传 `size`，
>       同一分类在不同场景给不同值（`svTraj` 地面 1.5~2.4 / 天球 0.38~0.42，差 5 倍）。
>   (b) **删除 `noteRefDist` / `_sd0Reg`** —— 旧实现给「每条精灵各自第一次被看到时的距离」
>       当标称距离，于是屏幕占比 = worldY / sd0，**完全由 sd0 决定而与 size 无关**，
>       同设置下像素高实测相差 2.9 倍（14.34px ~ 41.53px），这正是「有的大有的小」的根因。
>       现改为 `applySvNoteK(cam, refD, scn)` 的**场景统一 refD**：天球 `orbSky.def.dist`、
>       地面新增常量 `G_REF_DIST = 36`（与 `gDist` 同源；此前误传 `46`，那其实是 `wGroundCam` 的 fov）。
>   (c) **`applySvNoteK` 读 `matrixWorld` 前必须显式 `scn.updateMatrixWorld(true)`** ——
>       本函数位于主循环中 `updateCelestial` 之后、`rnd.render` 之前，而 three 的
>       `updateMatrixWorld` 由 `renderer.render()` 内部触发 ⇒ **本帧新建的精灵矩阵还是单位阵**，
>       `setFromMatrixPosition` 读出场景原点，所有这类精灵拿到**同一个** k
>       （天球侧 = cDist/RD = 1.2758，日出 29.78px vs 日落 18.31px，差 11.5px）。
>       而整点 / 日出日落注释在「动态绘制」模式下**每帧重建**（`trailSig` 含 `lst`），必然踩中。
>   (d) **`hourNoteSps` / `term4Grp` 清理必须补 `noteSplice(sp)`** —— 否则每帧往 `allNoteSps`
>       漏僵尸条目，`applyNoteStyles` / `applySvNoteK` 每帧遍历的其实是「历史残骸 + 当前精灵」。
>       （`disposeObj()` 内部已含 `noteSplice`，走它的清理路径天然干净。）
>   (e) 调试钩子 `window.SUNVIEW._notes()` 的返回项 `sd0` / `kf` 删除、新增 `pxH`（屏幕像素高）；
>       另新增**只读**出口 `window.__svGeom`（`THREE` / `iCam` / `iRoom` / `gCam` / `cCam` /
>       `gScene` / `cScene` / `iScene` / `IR`），供探针独立复算投影，无任何写入口。
> ④ **新增 `S.objEdge`（建筑 / 旗杆 / 树木 / 小人的立体边框）** —— 常态由 `on`/`color`/`op` 决定，
>   **选中态强制高亮蓝 `0x2563eb` + 0.95 且不受 `on` 影响**；新增 `facadeTexture`（八层叠加）
>   与配套的 `shade(hex,k)` / `rgba(hex,a)`。
> ⑤ **平面视图体积光重做** —— 双层壳（core 192 段 + sheath 160 段，`SV_SRGB_FN`），
>   `color / dia / sheath / edge / decay` 五项全部接入可调（DEF 叶子 205 → 209）。
> ⑥ **方位标注纳入全局文字样式（需求一·6）** —— 地面 `#svDirMarks` / 室内 `#svIndoorDirMarks`
>   是 **DOM 覆盖层**（`.svdm` / `.svidm`），此前字号写死在 CSS 里、完全绕过 `noteStyleFor`；
>   现由 `applyDirTextStyle()` 共用 `svNoteStyle('svDirMark')`，
>   并在 `NOTE_CAT_DEF` 新增 `svDirMark: { size:0.62, color:'#FFFFFF', op:1, weight:'400', align:'center', font:'default' }`
>   （该分类的 `rg()` 已在菜单中**禁用**，因为它已被全局总控接管）。
> ⑦ **菜单叶子数不变**（主模块 `MENU` 与太阳侧 `SUN_MENU` 的滑块 id 集合均无增删），
>   变的只是部分滑块的**量程与读数格式**（①）。`_stat_sunmenu.js` 仍报 `paths 245 / ids 270 / uniqIds 311`。
> ⑧ **新增只读调试出口与探针**：`tools/_probe_v43_dir.js`（9 项）、`_probe_v43_head.js`（20 项）、
>    `_probe_v43_tb.js`（18 项，总菜单；另有时间面板版 12 项）、`_probe_v43_fs.js`（9 项，字号口径）。
> ⚠️ **`tools/_probe_indoor.js` 自 v40 起一直静默失效**（进太阳视图的选择器
>    `button[data-view="sun"]` 在总菜单重构后已不存在），导致它把「光斑 0 次 / 相机 y=0」
>    当成产品缺陷报出来。v43 已改为 `button[data-sunview="ground"]`、并按「当前可见画布」取

> **v42 变更**（渲染 / 几何口径为主；太阳侧 `SUN_MENU` **叶子 +3**，主模块 `MENU` 无增删）：
> ①**「过物体顶部的光线」由整条长线改为贴顶点的短掠过段**（代码审查「改法 B」）——

**① 换行标注「第二行不出现」（影响需求⑤⑥）**

- 现象：勾选「显示日期（另起一行）」/「显示日地距离」后，开关状态与 `sp.userData.noteText`
  都已正确变成两 / 三行，但画面上始终只有第一行。
- 根因：`makeTextSprite` 的 `setText()` **只把 `userData.dpi` 归 0**，真正重建贴图的地方
  只有 `applyAll()` 里的 `spriteDPI(sp, noteDPI(size))`；而 `bindMenuLeaf` 的 `after`
  回调**晚于**本次 `applyAll()` —— 即 `setPath → applyAll() → persist() → after()`。
  于是「改写文本 → 置 dpi=0」之后没有任何一次重绘，贴图永远停在旧文本上
  （`_spdSig` 那条懒重写路径同样如此：`applySpeedDemo()` 只在下一帧才把文本写新，但下一帧
  也不会跑 `applyAll()`）。
- 修法：在 `bindMenuLeaf` 的 `after` 里补齐重绘 ——
  `orb.terms.date` → `refreshTermLabels(); applyAll();`；
  `spd.apsis{Name,Date,Dist}` → `updateSpeedDemo(); applyAll();`
  （近日点 / 远日点的文本由 `updateSpeedDemo()` 按 `_spdSig` 懒重写，必须先调它算出新文本，
  再 `applyAll()` 重绘）。**判据**：改写文本后 `sp.userData.dpi` 必须由 0 变回 1（探针实测）。

**② 近日点 / 远日点「日地距离」读数放大 1000 倍**

- `AU_M = 1.495978707e11` 的单位是**米**，而「亿 km」= 1e8 km = **1e11 m**；
  v28 的 `PERI_KM/APH_KM` 误用 `/ 1e8`，得到的其实是「10⁵ km」为单位的值却按「亿 km」标注，
  屏幕显示 `1470.98 亿 km`（应为 `1.4710 亿 km`）。
- 修正为 `/ 1e11`：近日点 **1.4710 亿 km**、远日点 **1.5210 亿 km**（与天文年历一致）。

## 一、节点数据结构（MENU 树）

每个节点是一个普通对象，字段如下（`menu.js` 顶部亦有注释）：

| 字段 | 含义 | 何时出现 |
|---|---|---|
| `name` | 显示名称（已剔除「（滑块控制）」这类控件说明文案） | 所有节点 |
| `children` | 子节点数组 | 有子级的分组 |
| `sw` | 开关控件 id（对应分组标题前的复选框） | 启用开关所在节点 |
| `swPath` | 该开关绑定的状态路径 | 与 `sw` 配套 |
| `ctl` | 内联挂在分组标题行上的控件（如「类型」下拉） | 少数分组 |
| `cat` | 注释分类名（走 `bindNoteCatCtl` 的注释分类样式） | `noteGrp()` 生成的分组 |
| `k` | 叶子控件类型：`sw` / `range` / `color` / `sel` / `num` / `btn` | 叶子控件 |
| `id` | 控件 id，与 `app.js` 绑定一一对应 | 叶子控件 |
| `path` | 状态路径，新控件由 `app.js` 通用绑定器按 path 自动接通 | 叶子控件 |
| `opts` | `sel` 的选项 `[ [值, 文案], … ]` | `k==='sel'` |
| `out` / `hex` | 滑块的数值回显 / 颜色的十六进制回显 id | 部分控件 |
| `map` / `fmt` | 滑块映射（百分比/绝对值/角度等）与格式化函数名 | 部分滑块 |
| `dash` | 虚线联动 key：**只有线型选中「虚线」时才可调**的行挂此键 | 虚线密度 / 虚实比 |
| `tzstripe` | 时区「相邻面交替填充」联动 key | 交替面颜色 / 透明度 |
| `raw` | 直接插入的原始 HTML（预设按钮、标注列表等特殊块） | 特殊块 |
| `tip` | 灰色说明文字 | 分组说明 |
| `gate` | **（v21.0）** 上级开关门控：逗号分隔的状态路径；这些路径不全为 `true` 时，本项置灰禁用 | 需先开上级的项 |
| `on` | `false` 表示框架未勾选（☐）；渲染时该节点及其子树整体不生成 | 可选 |

### 构造简写（`menu.js`）

```js
G(name, children, opts)      // 分组
use(id, name, opts)          // 引用 menu-ctrls.js 中已收割的控件

```

## 四、开关控制与状态联动

- 每个 `sw` / 控件通过 `path` 绑定到 `state`（如 `orb.planes.ecl`、`note.cats.ecl.on`、`style.fill.pd.op`）。
- `app.js` 的 `bindMenuTree()` 遍历 `MENU` 树，对 `k` 叶子调用通用绑定器
  `bindRange/bindColor/bindSelect/bindSwitch`；注释分类样式走 `bindNoteCatCtl`。
- **带 `path` 的叶子自动接通** —— 判定依据是「是否有 path/swPath」，不需要在 `app.js` 里逐个手写按钮 id。
- 带 `sw` 的分组开关改变时，既切换 `.nd.off`（收起子级），又经 `path` 改写 `state` 并触发 `applyAll()` 重绘。

### v21.0：注释显隐的三级层级（`gate` / `thingGateOn` / `.gated`）

注释的显隐由**三个层级的「与」运算**决定，任一层为假即不显示：

| 层级 | 判定位置 | 说明 |
|---|---|---|
| ① 全局文字注释总开关 | `note.master.on`（`noteStyleFor().show` 里判） | 菜单「📝 全局文字样式 › 全局文字注释开关」 |
| ② 地理事物开关 | `thingGateOn(cat)`（`app.js`） | 如 `dawn/dusk → state.term && state.dawn.on`、`orbit → state.orb.orbit.on`、`ecl → state.orb.planes.ecl`、`lat → state.graticule`（且经度注释还要 `state.grat.mer`、纬度注释要 `state.grat.par`） |
| ③ 注释分类 / 单项开关 | `noteSwitchOn(state.note.cats[cat], subKey)` | 由菜单的注释分类开关写入 |

```js
function thingGateOn(cat) {           // ② 地理事物
  switch (cat) {
    case 'dawn': return !!state.term && !!state.dawn.on;   // 先开「显示晨昏线」，再开「晨线」

    case 'ecl': return !!state.orb.planes.ecl;             // 先开「黄道面」
    default: return true;
  }
}
function spriteNoteGate(sp) {          // ③+②：三级同时为真才 ⇒ visible
  if (!thingGateOn(cat)) return false;
  ...
  return noteSwitchOn(state.note.cats[cat]);
}
```

#### 9.4.3 几何与实体的实现要点

* **共用一条大圆**：解算一次得到局部基 `e0 = Â`、`n = normalize(Â×B̂)`、`e1 = n×e0`
  （`makeBasis` 必须 det = **+1**），顶点方向 `dir = cos(gt·uSpan)·e0 + sin(gt·uSpan)·e1`。
  环线取 `uSpan = 2π`、劣弧取 `uSpan = θ` —— 两者由**同一个基**生成，
  因此严格共用同一条大圆，两个端点必然同时落在两条线上（探针用 `1 − B̂·dir(θ)` 断言，
  实测 1.11e-16）。
* 距离 = `R·θ`，`θ = acos(Â·B̂)`，`R = 6371.0088` km（IUGG 平均半径）；
  劣弧恒为 `θ ≤ 180°`，故 `0 ≤ d ≤ πR ≈ 20 015 km`，单位自适应在 `fmtGcdDist()` 里做。
* **距离标注的落点**：`normalize(e0 + normalize(Â×B̂)·sinθ)`。
  ⚠ 不能写成 `e0 + e1·sinθ` —— 那个式子只在 `θ = 90°` 时落在中点，
  一般情形会偏出大圆（这是被像素探针抓出来的真 bug：北京—东京那组标注曾落在
  `(47.40, 116.67)`，而正确值是 `(38.37, 128.38)`）。
* **半径分层**（drape 关闭时统一沿径向抬升 `GCD_LIFT = 0.34`）：

  | 元素 | 贴地半径 | renderOrder |
  |---|---|---|
  | 大圆环线 | `1.0200` | 21 |
  | 最短弧线 | `1.0215`（略高 → 稳稳叠在环线之上） | 22 |
  | 端点小球 | `1.0240` | 30 |
  | 三条文字注释 | `1.100`（端点标注 `1.070`） | 43 |

* **注释必须挂在 `earthNotesPass()` 里摆位**（渲染侧硬约束）：综合视图每个子窗在
  `renderer.render()` 前都要用**它自己的相机**重算一遍注释位置，`layoutGcdNotes()` 因此
  在两个分支（主视图 / 公转侧视图）各调一次，不能只在 `applyGcd()` 里算一次。
* `makeTextSprite()` 增补 `userData.setText(t)`：文本放进可变盒子 `box.txt`，
  `draw` 每次取当前文字；行数变化时同步 `ch` / `baseH` 并把 `dpi` 归零触发重绘 ——
  距离标注才能随测量结果换字而**不重建精灵**。
* **边界情况**：`|Â×B̂|² < 1e-12` 时两点共线，再用 `cosθ` 的符号区分 ——
  `cosθ > 0` → 重合（大圆不唯一，停止绘制并提示）；`cosθ < 0` → 对跖（大圆有无穷多条，
  仍取其中一条绘制，劣弧 = 半个大圆，距离恒为 `20 015 千米`）。
* 光标：`syncCanvasCursor()` 统一决定画布光标，取点模式下为十字；小人拖拽结束时
  也走这个函数（否则会把十字光标抹掉）。

### 11.2 绑定方式：**一个通用绑定器 + 一个状态对象**（零手写控件代码）

```js

             //   读 getPath(S, n.path) 写控件（sync 同时推进 sunBinders，供 applySun 回灌）
```

* 所有控件只认 `path`（点分路径），状态全部集中在 `S`（`sunview.js` 的持久化状态对象，

### 17.1 主模块：体积光柱实心化 + 边缘平滑过渡

`app.js` 光照与太阳光线 › 体积光柱（`volShaft`）：

| 项 | 旧（v37） | 新（v38） |
|---|---|---|
| 核心几何 | `VOL_UNIT_CYL = CylinderGeometry(1,1,1,64,1,**true**)`（开口） | `VOL_CORE_CYL = CylinderGeometry(1,1,1,64,1,**false**)`（封口 → 实心体积） |
| 外围几何 | 复用同一开口柱 | `VOL_SHEATH_CYL = CylinderGeometry(1,1,1,48,1,false)` |
| 径向淡出 | `alpha = uOp * pow(|dot(N,V)|, uFall)` | `alpha = uOp * pow(**smoothstep(0.0, uEdge, |dot(N,V)|)**, uFall)` |
| 核心参数 | `uOp = op*inten*1.0`，`uFall = 1.0` | 同左，另加 **`uEdge = 0.72`** |

* **平滑过渡**：`smoothstep(0.0, uEdge, f)` 先把轮廓附近（`f < uEdge`）压到 0 再取幂，

## 十八、v42 增量（物影光线改法 B · 平行光线根数 · 时间面板节点语义统一）

### 18.1 「过物体顶部的光线」：a / b 由「掠过方向 pd」一次推出（改法 B）

* **参数**（`SUN_MENU` 观察与测量 › 物影 › 过物体顶部的光线，受 `cbSvMeasRay` / `meas.ray` 门控）：

  | 控件 | 类型 | 路径 / 值域 | 默认 | 说明 |
  |---|---|---|---|---|
  | `rngSvMeasRayLen` | RANGE | `meas.rayLen` 0.5–126 step 0.5（`int1`/`raw1`） | **6** | 掠过段长度：太阳侧端点自顶端沿「指向太阳」方向前推的长度；**拉到 126（= `SUN_DIST`）即端点落在太阳中心**，平滑退回 v41 的整条长线 |
  | `rngSvMeasRayCount` | RANGE | `meas.rayCount` 1–5 step 1（`int1`/`raw`） | **1** | 平行光线根数（>1 时按 `_RAY_SPACING = 1.0` m 水平等间距偏移） |
  | `cbSvMeasRayToSun` | SW | `meas.rayToSun` | **false** | 连到太阳：端点一律取太阳中心（= v41 行为），`rayLen` 失效 |
  | `rngSvMeasRayW / clrSvMeasRay / rngSvMeasRayOp` | 沿用 | `meas.rayW / rayColor / rayOp` | — | 线粗细 / 颜色 / 透明度，语义不变 |

* **几何口径**（`updateMeas()`，务必与影长 / 多根直线保持自洽）：
  * `pd` = 单位掠过方向（**从物体顶端指向太阳**），`ra` = 太阳侧行程，`tDrop = H / pd.y`；
    `a = (顶端 + 水平偏移) + pd·ra`，`b = (顶端 + 同一水平偏移) − pd·tDrop`（⇒ `b.y = H − pd.y·tDrop = 0`）。
  * **常规模式**：`pd = dirOf(alt, az)`（平行光）⇒ 落点恰是影长线段的**影尖**，多根之间严格平行；
